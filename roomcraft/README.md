# RoomCraft AI

**사진 한 장으로 공간을 리모델링하고, 그 안에 배치된 가구를 그대로 수익으로 연결하는 AI 인테리어 스튜디오.**

첨부해 주신 화면 기획을 실제로 동작하는 React 앱으로 구현한 것입니다. Before/After 렌더부터
제휴 링크 생성·템플릿 판매·클라이언트 견적까지, 4개의 수익 모델이 하나의 흐름으로 이어집니다.

---

## 빠른 시작

```bash
cd roomcraft
npm install

npm run server   # 터미널 1 — API 서버 (8787)
npm run dev      # 터미널 2 — 웹 (5173)
```

API 키가 없어도, 서버를 안 띄워도 **전체 흐름이 그대로 동작합니다.**

| 상황 | 동작 |
|---|---|
| 서버 없음 | 목(mock) 렌더 + 로컬 크레딧. 화면 상단에 안내가 뜹니다. |
| 서버만 실행 | 계정·결제·크레딧 원장 동작. 렌더는 여전히 목. |
| 서버 + API 키 | 실제 AI 렌더/챗. 크레딧은 서버가 차감. |
| 서버 + Stripe 키 | 실제 Stripe Checkout. 없으면 dev 결제 시뮬레이터. |

```bash
cp .env.example .env   # 필요한 키만 채우면 됩니다
```

### 테스트

**두 종류의 서버 설정이 필요합니다.**

레이트 리밋 저장소가 메모리라 카운터가 실행 간에 누적됩니다. 가입 상한 검증은 낮은
상한이 필요하고, 브라우저 스위트는 여러 번 가입해야 해서 높은 상한이 필요합니다.

```bash
# 1) 리밋 검증 — 기본 상한(5/시간)
npm run server
npm run test:api          # 가입 폭주 차단까지 검증

# 2) 브라우저 스위트 — 상한을 올려서
RATE_LIMIT_SIGNUP_PER_HOUR=500 RATE_LIMIT_GLOBAL_PER_15MIN=20000 npm run server
node e2e-verify.mjs && node e2e-auth.mjs && node e2e-tracking.mjs
```

상한이 20을 넘게 설정된 서버에서는 `test:api` 가 가입 폭주 검증을 건너뜁니다 —
끝까지 돌리면 가입 예산을 소진해 브라우저 스위트가 가입에 실패하기 때문입니다.
서버를 재시작하면 카운터가 초기화됩니다.

```bash
npm run test:api    # API 통합 + 원장 + 링크 추적 + 인증/리밋 (55개)
node smoke.mjs      # 스튜디오 UI (20단계)
node e2e-auth.mjs   # 계정·결제·크레딧 브라우저 E2E (13단계)
node shoptest.mjs   # 쇼퍼블 이미지 태그 (11단계)
node e2e-tracking.mjs  # 클릭 추적·구독 갱신 (8단계)
node e2e-verify.mjs    # 이메일 인증·레이트 리밋 (6단계)
node e2e-a11y.mjs      # 비밀번호 재설정·가독성·테마 (14단계)

npm run test:e2e       # 브라우저 스위트 전체
```

모든 스위트가 `BASE_URL` 을 받습니다. 배포한 주소를 넣으면 실서버를 그대로 검증합니다.

### 눈으로 확인하기

```bash
npm run check:contrast                    # 팔레트 대비 (두 테마)
BASE_URL=http://localhost:8787 npm run sim    # 수익 흐름 한 사이클
```

`scripts/simulate.mjs` 는 서버 API 만 두드려 **가입 → 이메일 인증(크레딧 지급) → 결제 →
구독 갱신 → 렌더 차감 → 추적 링크 발급·클릭 → 정산 통계 → 원장** 을 한 번에 돌립니다.
같은 결제를 두 번 처리해 멱등성을, 허용되지 않은 대상 URL 을 넣어 오픈 리디렉트 차단을
함께 확인합니다. 결제는 dev 시뮬레이터를 쓰므로 Stripe 키가 설정된 환경에서는 멈춥니다.

## 4가지 수익 모델

### 0. 클릭 추적 — 수익 판단의 유일한 근거

앱의 사용자는 **창작자**지만 가구를 사는 사람은 **창작자의 독자**입니다. 수수료는 블로그·카톡으로
나간 링크에서 발생하므로, 그 링크가 추적되지 않으면 어떤 스타일·채널이 돈이 되는지 알 수 없습니다.

로그인 상태에서 내보내면 모든 링크가 `/r/:token` 추적 링크로 발급됩니다.

```
독자가 링크 클릭 → /r/:token → 클릭 기록 → 302 → 실제 쇼핑몰
```

- 같은 (사용자·제품·몰·채널) 조합은 토큰을 재사용해 통계가 흩어지지 않습니다
- 제휴 ID를 바꾸면 기존 토큰의 대상 URL이 갱신됩니다(이미 배포한 링크가 살아있음)
- 대상 호스트 화이트리스트로 **오픈 리디렉터 악용을 차단**합니다
- 원문 IP는 저장하지 않고, 일별 솔트를 섞은 해시로 방문자 중복만 구분합니다
- 기록에 실패해도 리디렉트는 반드시 수행합니다 — 통계 때문에 매출을 잃으면 안 됩니다
- 비로그인이면 원본 딥링크로 폴백합니다. 추적만 빠지고 기능은 그대로입니다

Earnings 패널의 **실측 클릭** 카드에서 채널·제품별 클릭과 방문자 수를 확인합니다.
기대 정산액(가정값)과 실측 클릭을 나란히 보여주어 둘을 혼동하지 않게 했습니다.

### 0-1. 쇼퍼블 이미지 태그 — 링크가 노출되는 지점
렌더가 끝나면 큐레이션 가구가 이미지 위에 태그로 찍힙니다.

- **클릭** → 상품 카드. 활성화된 전 채널 구매 링크가 바로 열립니다(추적 ID 자동 삽입).
- **드래그** → 태그 위치 이동. 렌더마다 가구 배치가 달라 초기 좌표는 추정값이라, 창작자가
  실제 가구 위로 맞출 수 있어야 합니다.
- 태그 추가/삭제, 무드보드 담기, 브랜드 공식몰 이동
- **쇼퍼블 HTML 내보내기** — 이미지와 태그 위치를 그대로 담은 HTML. 블로그에 붙여넣으면
  독자가 이미지의 태그를 눌러 제휴 링크로 이동합니다. 외부 CSS/JS 없이 인라인 스타일만
  사용합니다(블로그 에디터 대부분이 `<style>`/`<script>` 를 제거하므로).

태그는 After 이미지의 상품이라 비교 슬라이더가 Before 쪽을 덮으면 숨겨집니다. 그래서 초기
위치는 슬라이더 기본값(50%) 오른쪽에만 배치합니다.

### 2. 템플릿 마켓 판매
현재 스타일·강도·큐레이션 구성을 하나의 프리셋으로 묶어 판매 등록. 플랜에 따라 70~90% 정산.

### 3. 클라이언트 납품 견적서
가구 마진율·디자인 피·부가세를 설정하면 원가/청구액/**디자이너 순이익**이 자동 계산됩니다.
텍스트 복사 및 파일 저장 지원.

### 4. 구독 & 크레딧
Free / Creator($19) / Pro Creator($49) / Studio($149) 4개 플랜 + 크레딧 팩.
렌더 1회 = 5크레딧, 챗 1턴 = 1크레딧.

**크레딧은 서버 권한입니다.** 로그인하면 잔액의 진실은 서버에 있고 클라이언트는 표시만 합니다.

## 계정 · 결제 · 크레딧 (서버)

### 크레딧을 원장(ledger)으로 둔 이유
잔액을 컬럼 하나로 들고 있으면 동시 요청에서 값이 덮이고, 이중 지급을 사후에 추적할 수 없습니다.
`credit_ledger` 에 모든 변동을 append 하고 **잔액 = SUM(delta)** 로 계산합니다.

- 차감은 잔액 확인과 같은 트랜잭션 안에서 → 동시 요청이 잔액을 음수로 만들 수 없음
- `(reason, ref)` 유니크 인덱스 → 같은 결제/요청으로 두 번 지급 불가
- 렌더 실패 시 자동 환불 기록이 남음 (`render:refund`)
- 계정 모달에서 전체 원장을 확인 가능

### 결제 흐름
```
클라이언트 → POST /api/payments/checkout   payments 행 생성 (pending)
                    ↓
      Stripe Checkout  또는  dev 시뮬레이터
                    ↓
Stripe 웹훅 → fulfillPayment(paymentId)
              UPDATE ... WHERE status='pending'  ← 0행이면 이미 처리됨
              플랜 반영 + 원장에 크레딧 적립
```

지급은 두 프로바이더가 **같은 `fulfillPayment` 함수**를 씁니다. 토스페이먼츠 등을 추가할 때는
체크아웃 생성과 웹훅 검증만 붙이면 됩니다.

- 웹훅 서명 검증 실패는 **반드시 400 으로 거절**합니다. 여기를 통과시키면 누구나 크레딧을 받습니다.
- `/api/payments/dev/complete` 는 Stripe 키가 설정되면 **자동으로 비활성화**됩니다.

### 계정
- 비밀번호: `scrypt` (사용자별 salt, node:crypto — 외부 의존성 없음)
- 세션: DB 저장 토큰 + httpOnly 쿠키. JWT 와 달리 즉시 폐기 가능
- 로그인 실패 메시지는 계정 존재 여부를 흘리지 않도록 통일

### 이메일 인증 — 크레딧 지급 시점이 핵심

**크레딧은 가입이 아니라 이메일 인증을 마쳐야 지급됩니다.** 가입 시점에 주면 이메일을
확인하지 않고 계정을 찍어내 무료 렌더를 무한히 쓸 수 있고, 그 비용은 렌더 API 실비로
직접 나갑니다.

- 인증 링크 24시간 만료, 1회용. 재발송 시 기존 미사용 토큰은 무효화
- 지급 ref 를 사용자 ID 로 고정해 재인증해도 중복 지급 불가
- `SMTP_URL` 이 없으면 링크를 콘솔에 출력하고, 개발 환경에 한해 API 응답에도 실어
  메일 서버 없이 흐름 전체를 확인할 수 있습니다 (운영에서는 노출되지 않습니다)
- 마이그레이션 시 기존 계정은 인증된 것으로 승계됩니다

### 비밀번호 재설정

`email_tokens` 에 `purpose='reset'` 로 저장하며, 인증과 같은 구조입니다.

- 링크 1시간 만료·1회용 (인증 링크보다 짧게 — 계정을 통째로 넘겨주는 링크입니다)
- **계정 존재 여부를 흘리지 않습니다** — 가입되지 않은 이메일에도 동일한 응답과 안내
- 비밀번호 변경 시 **기존 세션을 전부 폐기**합니다. 탈취당해 재설정하는 상황에서
  공격자의 세션이 살아 있으면 재설정이 무의미합니다
- 재설정 링크를 열었다는 것은 메일함 소유를 뜻하므로 이메일 인증도 함께 처리합니다

| 전체 API | 600회/15분 | IP |

모두 `RATE_LIMIT_*` 환경변수로 조정합니다. 두 가지를 주의하세요.

- **`TRUST_PROXY`** — 프록시 뒤에 배포하면 `req.ip` 가 프록시 IP 가 되어 전원이 한 덩어리로
  묶입니다. 반대로 무조건 신뢰하면 `X-Forwarded-For` 위조로 우회됩니다. 신뢰할 홉 수를
  명시하세요.
- **IPv6** — 가입자 한 명에게 대역이 통째로 배정되므로 주소만 바꾸면 우회됩니다.
  `ipKeyGenerator` 로 /56 서브넷을 묶습니다.

저장소가 메모리라 서버를 재시작하면 카운터가 초기화됩니다. 인스턴스를 여러 대로 늘리면
공유 저장소(Redis 등)가 필요합니다.

## 가독성 · 접근성

작업 전 상태를 측정해 보니 글자의 절반 이상이 10~11px 이었고, 76곳에서 쓰던
`text-mist-500` 은 **정의되지 않은 토큰**이라 클래스가 생성되지 않은 채 부모 색을
물려받고 있었습니다.

| 항목 | 이전 | 이후 |
|---|---|---|
| 최소 글자 크기 | 9px | 12px (rem 기반) |
| `mist-500` | 미정의 (의도한 색이 적용 안 됨) | 두 테마 모두 AA 4.5:1 이상 |
| 패널·버튼 경계선 | `border-ink-700` = 1.29:1 (사실상 안 보임) | `line` 3:1 이상 · `line-soft` 구분선 |
| 화면 밝기 | 다크 고정 | 밝게(기본) / 어둡게 전환 |
| 버튼 최소 높이 | 24~26px | 34/40/48px (WCAG 2.2 최소 24px 충족) |
| 입력 필드 | 높이 지정 없음 | 최소 42px |
| 키보드 포커스 | `outline-none` 만 있고 대체 표시 없음 | `:focus-visible` 링 |
| 움직임 | 항상 애니메이션 | `prefers-reduced-motion` 존중 |

### 글자 크기 조절

Tailwind 의 `text-xs/sm/base` 는 rem 기반이므로, 루트 폰트 크기 하나만 바꾸면
레이아웃을 건드리지 않고 앱 전체 글자가 비율을 유지한 채 커집니다. 절대 px 지정
132곳을 rem 스케일로 옮겨 이 방식이 전체에 적용되게 했습니다.

헤더의 **가 가 가** 버튼으로 보통(16px) · 크게(18px) · 아주 크게(20px) 를 고르고,
선택은 브라우저에 저장됩니다.

### 밝게 / 어둡게

색은 컴포넌트가 아니라 `src/index.css` 의 토큰이 쥐고 있습니다. Tailwind v4 유틸리티는
값을 인라인하지 않고 `var(--color-*)` 를 그대로 참조하므로, `html[data-theme='light']`
에서 변수만 뒤집으면 50여 개 컴포넌트를 한 줄도 고치지 않고 테마가 바뀝니다.

토큰을 손볼 때 걸린 문제가 두 가지 있었습니다.

- **`ink-700` 이 면과 선을 겸하고 있었습니다.** 배지 배경(`bg-ink-700`)이자 버튼
  테두리(`border-ink-700`)라, 테두리가 보이도록 값을 올리면 그 위에 얹힌 글자 대비가
  같이 무너집니다. 선 색을 `line-soft`(구분선) · `line`(컨트롤 경계) · `line-strong`(호버)
  으로 떼어냈습니다.
- **강조색은 램프를 뒤집으면 안 됩니다.** `#f0a437` 은 흰 배경 위에서 1.9:1 이라
  글자로 쓸 수 없습니다. 색상(hue 35°)은 유지한 채 명도만 내려 라이트 테마 값을 정했고,
  브랜드 면 위의 글자색은 `on-brand` 로 분리했습니다 (다크는 검정, 라이트는 흰색).

전환은 헤더의 **☀ 밝게 / ☾ 어둡게** 버튼이며 선택은 브라우저에 저장됩니다. 첫 페인트 전
적용은 `public/boot.js` 가 맡습니다 — React 안에서 적용하면 기본값으로 한 번 그려진 뒤
바뀌어 화면이 번쩍입니다. CSP 가 `script-src 'self'` 라 인라인 스크립트는 막히고,
인라인 해시를 CSP 에 넣으면 스크립트를 고칠 때마다 해시를 같이 고쳐야 하므로 별도 파일로 뒀습니다.

### 팔레트 대비 검사

```bash
npm run check:contrast        # 두 테마 · 실패하면 종료 코드 1
```

`scripts/contrast.mjs` 가 `index.css` 에서 토큰을 직접 읽어, 앱에서 실제로 겹쳐 쓰는

합성한 뒤 계산합니다. 기준은 본문 4.5:1 · 컨트롤 경계 3:1 · 장식 구분선은 그보다 낮게
두되, 무엇을 왜 낮게 뒀는지는 파일 안에 적어 뒀습니다.

### 자동 검증

`e2e-a11y.mjs` 가 실제 렌더된 화면에서 다음을 검사합니다.

- 12px 미만 글자가 없는지

## 배포

### 구조

프로덕션에서는 **웹과 API 가 같은 오리진**입니다. API 서버가 빌드된 SPA 를 직접 서빙합니다.

```
브라우저 → [Fly/Render 프록시] → Express (8787)
                                   ├─ /api/*  API
                                   ├─ /r/:id  제휴 추적 리디렉트
                                   └─ /*      dist/ (SPA)
```

이렇게 한 이유:
- CORS 가 사라지고 쿠키 설정이 단순해집니다
- 제휴 추적 링크 `/r/:id` 가 웹 도메인에서 그대로 동작합니다 (분리하면 웹 쪽에 그 경로가 없습니다)
- 배포 단위가 하나입니다

개발에서는 Vite(5173) ↔ API(8787) 로 나뉘고, 그때만 CORS 와 `/api`·`/r` 프록시가 켜집니다.

### 기동 전 설정 점검

운영 사고는 대개 코드가 아니라 설정에서 납니다. `NODE_ENV=production` 이면 서버가
뜨기 전에 확인하고, 다음 중 하나라도 걸리면 **기동을 중단합니다**.

| 검사 | 걸리면 생기는 일 |
|---|---|
| `APP_URL` 없음 | CORS·결제 리디렉트·추적 링크가 모두 잘못된 주소를 가리킴 |
| `APP_URL` 이 http | 세션 쿠키가 secure 로 발급되어 전달되지 않음 → 로그인 불가 |
| `STRIPE_SECRET_KEY` 없음 | dev 결제 시뮬레이터가 켜져 **무료 지급 경로가 열림** |
| `STRIPE_WEBHOOK_SECRET` 없음 | 웹훅 검증 불가 → 결제해도 크레딧이 지급되지 않음 |
| `SMTP_URL` 없음 | 인증 메일 발송 불가 → 신규 가입자가 크레딧을 못 받음 |

경고만 하는 항목: `CLICK_SALT`(재시작 시 방문자 판정 끊김), `TRUST_PROXY`(프록시 뒤에서
전원이 한 IP 로 묶임), AI 키(목 모드로 동작), `DATABASE_PATH`(재배포 시 데이터 소실).

### Fly.io

```bash
fly launch --no-deploy
fly volumes create roomcraft_data --size 1      # SQLite 영속 볼륨
fly secrets set STRIPE_SECRET_KEY=... STRIPE_WEBHOOK_SECRET=... \
                SMTP_URL=... GEMINI_API_KEY=... ANTHROPIC_API_KEY=... \
                CLICK_SALT="$(openssl rand -hex 16)"
fly deploy
```

`fly.toml` 의 `APP_URL` 을 실제 도메인으로 바꾸세요. 볼륨을 마운트하지 않으면
**재배포마다 계정·크레딧·클릭 기록이 사라집니다.**

배포 후 Stripe 대시보드에서 웹훅을 등록합니다.

```
https://<도메인>/api/payments/webhook
이벤트: checkout.session.completed, invoice.payment_succeeded,
        invoice.payment_failed, customer.subscription.deleted
```

### 확장에 대한 주의

지금 구조는 **인스턴스 1대 전용**입니다.

- SQLite 파일 하나를 씁니다 → 여러 인스턴스가 같은 파일을 쓸 수 없습니다
- 레이트 리밋 저장소가 메모리입니다 → 인스턴스마다 카운터가 따로 셉니다

트래픽이 늘어 확장이 필요하면 Postgres 와 공유 저장소(Redis)로 옮겨야 합니다.
SQL 을 `server/*.js` 밖으로 새지 않게 유지해 둬서, 이전 시 그 파일들만 바뀝니다.

### 보안 헤더

CSP 를 좁게 잡았습니다(외부 스크립트·스타일을 쓰지 않으므로). 렌더 결과가 data URL 이라
`img-src` 에만 `data:` 를 허용합니다. 그 밖에 `X-Content-Type-Options`, `Referrer-Policy`,
`X-Frame-Options: DENY`, `Permissions-Policy`, 그리고 운영에서는 HSTS 를 붙입니다.

`/assets` 아래 파일은 Vite 가 콘텐츠 해시를 붙이므로 1년 immutable 로 캐시하고,
`index.html` 은 `no-cache` 로 항상 최신을 받게 합니다.

### DNS 설정

도메인을 정한 뒤 아래 순서로 설정합니다. **④번이 실제 병목입니다** — 인증 메일이
도착하지 않으면 신규 가입자가 크레딧을 못 받고 그대로 이탈합니다.

#### ① 앱 연결 (Fly 기준)

```
A     @      <fly가 알려주는 IPv4>
AAAA  @      <fly가 알려주는 IPv6>
CNAME www    <앱>.fly.dev
```

```bash
fly certs add roomcraft.com
fly certs add www.roomcraft.com
```

`fly.toml` 의 `APP_URL` 도 실제 도메인(https)으로 바꿔야 합니다. http 로 두면
세션 쿠키가 secure 라 로그인이 아예 되지 않고, 서버가 기동을 거부합니다.

#### ② 발송 도메인은 앱 도메인과 같게

`MAIL_FROM=RoomCraft <no-reply@roomcraft.com>` 처럼 앱과 같은 도메인을 쓰세요.
**DMARC 는 `From:` 헤더의 도메인을 기준으로 판정**하므로, 발신 도메인이 다르면
SPF·DKIM 을 아무리 잘 맞춰도 정렬(alignment)에서 실패합니다.

#### ③ SPF

도메인당 **정확히 하나**만 둡니다. 두 개 이상이면 permerror 로 전부 무효가 됩니다.

```
TXT  @   v=spf1 include:<발송서비스가 안내하는 도메인> ~all
```

- `~all`(softfail) 로 시작해 안정되면 `-all`(hardfail) 로 조입니다
- `+all` 은 절대 쓰지 마세요 — 누구나 이 도메인으로 발송할 수 있게 됩니다
- **DNS 조회 10회 제한**이 있습니다. `include` 를 여러 개 붙이면 금방 넘고,
  넘으면 SPF 전체가 무효가 됩니다

#### ④ DKIM

발송 서비스가 셀렉터와 공개키를 발급합니다. 서비스마다 셀렉터 이름이 다릅니다.

```
TXT  <셀렉터>._domainkey   v=DKIM1; k=rsa; p=<공개키>
```

`p=` 가 비어 있으면 **폐기된 키**입니다(RFC 6376). 검사기가 이 경우도 잡아냅니다.

#### ⑤ DMARC

Gmail·Outlook 은 대량 발신자에게 DMARC 를 요구합니다. 없으면 인증 메일이
스팸함으로 갑니다.

```
TXT  _dmarc   v=DMARC1; p=none; rua=mailto:dmarc@roomcraft.com
```

`p=none` 은 **모니터링 단계**입니다. 리포트(`rua`)로 정렬 실패를 확인한 뒤
`quarantine` → `reject` 로 올리세요. 처음부터 `reject` 로 두면 설정 실수가
그대로 메일 전면 차단이 됩니다.

#### 점검

```bash
node scripts/mail-doctor.mjs --domain roomcraft.com
node scripts/mail-doctor.mjs --domain roomcraft.com --selector s1 --send me@example.com
```

검사 항목:

| 항목 | 무엇을 보는가 |
|---|---|
| `From:` 정렬 | `MAIL_FROM` 도메인이 점검 도메인과 같은지 (DMARC 판정 기준) |
| SPF | 존재·중복·`all` 정책·**DNS 조회 10회 제한** |
| DKIM | 셀렉터별 공개키. 미지정 시 흔한 셀렉터 16개를 훑음. `p=` 빈 폐기 키 감지 |
| DMARC | 정책 단계와 `rua` 리포트 주소 |
| MX | 반송·문의 수신 가능 여부 |
| SMTP | 실제 연결(`verify`)과 `--send` 로 실제 발송 |

"레코드 없음" 과 "DNS 조회 실패" 를 구분합니다 — 타임아웃을 '없음' 으로 보고하면
멀쩡한 설정을 고치려 들게 됩니다.

`--send` 로 받은 메일은 **원문의 `Authentication-Results` 헤더**에서
`spf=pass`, `dkim=pass`, `dmarc=pass` 를 확인하세요. 받은편지함에 왔다고
끝이 아닙니다.

#### 새 도메인 워밍업

갓 등록한 도메인은 발신 평판이 없어 초기에 스팸 분류될 수 있습니다.
오픈 전 며칠간 소량으로 실제 발송해 평판을 쌓으세요.

## 단위 경제성

렌더 API 단가는 공급자 정책에 따라 바뀌므로 코드에 상수로 박지 않았습니다.
대신 계산기를 두어, 실제 단가를 넣으면 플랜별 마진이 바로 나옵니다.

```bash
node scripts/unit-economics.mjs <렌더단가USD> <챗단가USD> <소진율>
node scripts/unit-economics.mjs 0.04 0.02 1
```

플랜·크레딧 값은 `src/data/plans.ts` 를 직접 읽으므로, 가격을 바꾸면 계산도 따라옵니다.

**손익분기 렌더 단가** (크레딧을 전부 렌더에 쓴다고 가정한 최악의 경우):

| 상품 | 매출 | 렌더 수 | 분기 단가 |
|---|---|---|---|
| Creator | $19 | 40회 | **$0.47** |
| Pro Creator | $49 | 120회 | **$0.41** |
| Studio | $149 | 480회 | **$0.31** |
| 크레딧 1,150개 팩 | $69 | 230회 | **$0.30** |

가장 빡빡한 상품이 $0.30입니다. 렌더 단가가 이를 넘으면 **헤비 유저에게 팔수록 손해**입니다.

**챗 원가 참고** — Claude Opus 5 기준 입력 약 1,300토큰 / 출력 약 550토큰이면
턴당 약 $0.02입니다. (Opus 5 $5/$25 per MTok, claude-api 스킬 캐시 2026-06-24 기준.
확정 단가는 anthropic.com/pricing 에서 확인하세요.) 챗은 1크레딧이라 어느 플랜에서든
마진이 남습니다 — 관리해야 할 건 렌더입니다.

**Free 플랜은 순수 비용입니다.** 가입 1건당 렌더 4회. 레이트 리밋과 이메일 인증이
없으면 자동 가입으로 이 비용에 상한이 없습니다.
