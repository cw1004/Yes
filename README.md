# SkinLab AI — AI 닥터 상담형 피부 진단 · 전후 비교 · 커머스 수익화 앱

문진 6문항을 받고 카메라로 얼굴을 촬영하면, **브라우저 안에서** 피부를 9개 지표로 분석한 뒤
AI 상담 캐릭터 **닥터 세라**가 진료 흐름 그대로 짚어줍니다.
4주 뒤 재촬영하면 **전·후 사진 슬라이더**로 무엇이 실제로 달라졌는지 확인합니다.
간단한 소견은 무료로, 원인 분석·관리 순서·4주 플랜은 결제 후에 제공합니다.
그리고 측정된 피부톤(ITA°)·언더톤·고민 지표에 맞춰 화장품을 추천하고,
쿠팡 / 올리브영 / 네이버 / 11번가 / Amazon 오퍼를 **한 화면에서 랭킹·비교**해 구매로 연결합니다.

```bash
npm start          # http://localhost:8787
npm test           # 36개 테스트 (분석 엔진 + 상담 엔진 + API)
npm run simulate   # 실사용 리허설 5개 페르소나 × 전체 여정 (91개 검사)
npm run build:demo # 서버 없이 도는 단일 파일 데모 (dist/demo.html)
```
의존성 0개 — Node 20+ 내장 모듈만 사용합니다.

## 1. 무엇이 어떻게 측정되는가

이미지를 sRGB → **CIE Lab** 으로 옮긴 뒤, 얼굴 존별로 계산합니다.

| 지표 | 계산 방식 |
|---|---|
| 피부톤 | 피부 픽셀 평균 Lab → **ITA°** → Fitzpatrick I~VI, a\*/b\* 비율로 언더톤 |
| 톤 균일도 | 피부 L\* 표준편차 |
| 홍조·민감도 | a\* 상위 95퍼센타일 − 평균 |
| 유분 밸런스 | T존(이마·코) 정반사 픽셀 비율 vs U존 |
| 모공·피부결 | 코·볼 라플라시안 에너지 90퍼센타일 |
| 색소침착 | 국소 중앙값 대비 어두운(그리고 b\*가 높은) 픽셀 면적비 |
| 다크서클 | 눈밑 존 L\* vs 볼 L\* 차이 |
| 주름·탄력 | 눈가·이마의 세로 방향 그래디언트 우세도 |
| 수분·투명도 | 결 거칠기 + 유분 부족 + 톤 편차 복합 추정 |

- 얼굴 검출은 브라우저 `FaceDetector` 가 있으면 사용하고, 없으면 촬영 가이드 타원을 씁니다.
- 피부 픽셀은 YCbCr + HSV + RGB 세 규칙 중 **2개 이상** 만족해야 통과합니다(머리카락·배경 배제).
- 촬영 전 **품질 게이트**(밝기 / 초점 / 얼굴 크기)가 먼저 걸러 재촬영을 유도합니다.

**톤 보정(베버의 법칙)**: 결·주름·다크서클은 ΔL 로 재는데, 같은 요철이라도 어두운 피부에서는 ΔL 이 작게 나옵니다.
절대값으로 채점하면 짙은 톤일수록 점수가 부풀어 "손댈 게 없습니다"라는 잘못된 결론이 나오므로,
지각 대비(ΔL/L)를 기준 밝기 L\*65 로 환산해 채점합니다. 피부 픽셀 판정의 밝기 하한도 이미지 평균에서 역산합니다
— 고정하면 Fitzpatrick V~VI 가 실내 조명에서 통째로 '피부 아님'으로 떨어집니다.

> 참고용 정보이며 의료기기·의학적 진단이 아닙니다. UI에 항상 고지됩니다.

## 1-A. AI 닥터 "닥터 세라"

실제 진료 흐름을 그대로 따라갑니다: **문진 확인 → 불일치 지적 → 시진 소견 → 종합 소견 → 관리 순서 → 주의 → 재진 예약**.

가장 큰 값은 **자각과 측정이 어긋나는 지점**을 짚는 단계입니다.
"건성이라고 하셨는데 T존 광택이 28%입니다. 수분 부족을 유분으로 보상하는 상태라, 유분 잡는 제품을 쓰면 더 나빠집니다."
— 흔한 오판이고, 실제로 고객이 가장 크게 반응하는 대목입니다.

- 기본 엔진은 **규칙 기반**(`public/js/engine/consult.js`)입니다. 키 없이, 오프라인에서, 지연 없이 항상 같은 품질로 나오고 무엇을 말할지 전부 추적 가능합니다.
- `ANTHROPIC_API_KEY` 가 있으면 `server/doctor.js` 가 그 대본을 Claude(`claude-opus-5`)로 **문장만** 다듬습니다.
  모델이 수치·순서·성분을 바꾸면(길이·stage 불일치) 통째로 버리고 규칙 대본으로 되돌아갑니다 — 지어낸 숫자는 곧 의료 오정보이기 때문입니다.
- SDK는 **optionalDependency** 입니다. 설치하지 않아도 앱은 그대로 동작합니다.

### 표현 규칙 (중요)

'진단·처방·치료' 대신 **'소견·관리·제안'** 을 씁니다. 캐릭터는 화면에서 *AI 가상 캐릭터 · 의료 행위가 아님* 을 항상 고지합니다.
한국에서 진단·처방을 표방하면 의료기기 인허가 대상이 되고, "전문의보다 낫다"류의 비교 표현은 표시광고법 위반이자 앱 심사 리젝 사유입니다.
체감은 상담처럼, 표기는 관리 가이드로 설계했습니다.

## 1-B. 전 / 후 사진 비교

- 촬영본은 **IndexedDB(기기 안)** 에만 저장됩니다(`public/js/storage.js`, 최대 24장, 오래된 것부터 정리).
- 비교 화면은 `clip-path` 슬라이더로 두 장을 겹쳐 보여주고, 최근 측정에서 70점 미만인 부위에 **마커**를 얹습니다.
- 항목별 전/후 점수 변화(▲▼/유지)와 **닥터의 재진 소견**(무엇이 반응했고 무엇이 내려갔는지)을 함께 냅니다.
- 14일 미만 간격이면 "turnover 주기가 28일이라 지금 차이는 조명·컨디션 영향일 수 있다"고 먼저 말합니다.

## 2. 프라이버시 — 사진은 서버로 가지 않습니다

분석은 전부 브라우저에서 끝나고, 서버로는 **숫자 지표와 문진 선택지만** 전송됩니다.
`POST /api/analysis` 의 본문에 이미지·픽셀 데이터가 포함되는 경로는 없습니다.
전/후 비교용 사진도 IndexedDB에만 남으므로, 다른 기기나 시크릿 모드에서는 보이지 않습니다(화면에 그렇게 안내합니다).
회원가입 없이 익명 서명 토큰으로 시작해 이탈을 줄입니다.

## 3. 수익화 구조

| 축 | 내용 |
|---|---|
| 리포트 언락 | ₩4,900 / 1회 (7일 열람) |
| 월간 멤버십 | ₩9,900 — 무제한 진단, 변화 추적, 리마인더, 광고 제거 |
| 연간 멤버십 | ₩79,000 — 2개월분 무료 |
| 제휴 커머스 | 판매처별 수수료(2.8~8%) · 클릭→전환 포스트백으로 확정 |
| 객단가 상승 | 진단 기반 **4주 루틴 풀세트 번들**(묶음가 노출) |
| 재방문 | 4주 뒤 재측정 → 점수 변화 그래프 → 제품 교체 제안 |

**무료/유료 경계는 서버에서 강제**됩니다. 결제 전에는 잠긴 지표 값이 응답에 아예 포함되지 않습니다
(`server/index.js` 의 `buildReport`). 클라이언트 CSS로 가리는 방식이 아닙니다.

### 랭킹 공식 (`public/js/engine/ranking.js`)

```
총점 = 적합도 × 0.55 + (전환기대 × 0.30 + 수익기여 × 0.15) × (0.3 + 0.7 × 적합도)
```

상업 점수를 **적합도로 감쇠**시킵니다. 이렇게 하지 않으면 수수료율만 높은 비관련 상품이
1위로 올라오고, 추천 신뢰가 깨져 결국 재방문과 구독이 함께 줄어듭니다.
각 카드에는 순위 근거(`reasons`)와 제휴 고지를 함께 노출합니다.

판매처 오퍼는 가격 45% / 배송·신뢰 35% / 수익 기여로 정렬하고 **최저가 배지**를 항상 표시합니다.

## 4. 화면

홈 → **문진 6문항** → 촬영(실시간 품질 코칭) → 분석 → **닥터 세라 상담**(한 줄씩 타이핑)
→ 페이월 → **전체 상담 + 전문 리포트**(9지표·원인/관리·AM/PM 루틴·4주 플랜·성분)
→ **맞춤 추천**(스킨케어 매칭 / 베이스 메이크업 톤 매칭 + 판매처 비교)
→ 4주 뒤 재촬영 → **전·후 비교**(슬라이더·부위 마커·항목별 변화·재진 소견)

`/admin.html` 은 매출·퍼널·판매처별 EPC 대시보드입니다 (ADMIN_TOKEN 필요).

## 6-A. 실사용 리허설 (`npm run simulate`)

단위 테스트가 함수를 잠근다면, 이 스크립트는 사람이 실제로 밟는 경로를 통째로 돕니다.
5개 페르소나(20대 지성 / 30대 자각 불일치 / 40대 색소 / 10대 문진 스킵 / 딥 스킨톤)로
문진 → 촬영 → 상담 → 결제 → 추천 → 제휴 클릭 → 재측정 → 전후 비교까지 밟고,
엣지 케이스(어두운 사진, 1회권 재사용, 잘못된 쿠폰, 측정 전 진입)와 서버 매출 집계까지 검증합니다.

`SIM_SHOTS=1` 로 단계별 스크린샷을 남깁니다. 이 리허설이 실제로 잡아낸 결함:

| 발견 | 조치 |
|---|---|
| Fitzpatrick VI 가 실내 조명에서 미검출 | 밝기 하한을 이미지 평균에서 역산 (`adaptiveFloors`) |
| 짙은 톤일수록 총점이 부풀어 오름 | ΔL 지표에 베버 보정 적용 |
| 딥 톤에 0% 매칭 호수를 "추천"으로 노출 | 셰이드 커버리지 확장 + 미커버 시 매칭 대신 경고 표시, 랭킹 강등 |
| 무료 상담의 핵심 후크가 5초 뒤에 등장 | 타이핑 속도 조정, 재생 완료 상태를 DOM 에 노출 |

## 6-B. 단일 파일 데모 (`npm run build:demo`)

`dist/demo.html` 하나만 열면 서버 없이 전 기능이 돕니다. 링크로 공유하거나 오프라인에서 시연할 때 씁니다.

- ES 모듈들을 의존성 순서로 이어붙이고 import/export 를 제거해 인라인 모듈 하나로 만듭니다(최상위 이름 충돌은 빌드 시 에러).
- 서버가 하던 권한 게이팅·결제·랭킹은 `scripts/demo-runtime.js` 가 브라우저에서 대신합니다. **결제는 모의 결제이고 실제 청구되지 않습니다.**
- 운영 빌드로 쓰면 안 됩니다 — 무료/유료 경계가 클라이언트에 있어 우회 가능합니다. 그 경계는 서버(`server/index.js`)에서만 강제해야 합니다.

## 7. 운영 전 반드시 할 일

1. `data/products.json` 은 **샘플 시드**입니다. 가격·재고·평점을 파트너 API 실데이터로 교체하세요.
2. `SKINLAB_SECRET` / `ADMIN_TOKEN` 교체, HTTPS 종단 적용.
3. JSON 스토어 → RDB 전환 (`server/store.js` 인터페이스 유지).
4. 각 제휴 프로그램 약관에 맞는 고지 문구 확인 (현재 랭킹 근거 + 수수료 고지 노출 중).
5. 촬영 데이터 처리 방침·의료기기 아님 고지를 앱스토어 심사 기준에 맞게 재검토.
6. 닥터 캐릭터 문구를 법무 검토에 올릴 것 — 의료 표현 금지 규칙은 코드(테스트 `상담문에 의료 표현을 쓰지 않는다`)로 잠가뒀지만, 마케팅 카피는 코드 밖에 있습니다.
