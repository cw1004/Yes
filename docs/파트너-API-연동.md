# 샘플 데이터 → 실제 판매처 데이터로 바꾸기

> 처음 하시는 분을 위한 문서입니다. **코드를 고칠 일은 거의 없습니다.**
> 대부분은 신청하고, 승인을 기다리고, 키를 `.env` 에 붙여넣는 일입니다.

---

## 0. 먼저 알아야 할 것 — 이건 한 덩어리가 아닙니다

"판매처 API 를 붙인다"는 말 안에 성격이 다른 세 가지가 섞여 있습니다.

| | 무엇 | 어디서 오나 | 자동화 |
|---|---|---|---|
| ① 상품·가격 | 이름, 가격, 재고, 배송 | 판매처 API 또는 CSV | 자동 |
| ② 제휴 링크 | 클릭을 내 실적으로 잡아주는 추적 링크 | 제휴 프로그램 승인 후 발급되는 ID | 자동 |
| ③ 수수료율 | 팔리면 몇 % 받는지 | 각 프로그램의 **요율표를 보고 사람이 입력** | 수동 |

그리고 **API 가 절대 주지 않는 네 번째**가 있습니다.

> **"이 제품이 지성 피부의 모공에 맞는가", "이 호수의 ITA 는 몇 도인가"**
>
> 이건 어느 판매처 API 에도 없습니다. 사람이 정해야 하고, 그게 이 앱의 진짜 자산입니다.
> 가격은 누구나 긁어올 수 있지만 이 매칭은 못 베낍니다.
> 자리는 `data/curation.json` 에 이미 마련돼 있고, 현재 20개 제품이 채워져 있습니다.

즉 **API 는 가격만 최신으로 바꿔주는 역할**이고, 추천의 근거는 계속 사람이 만듭니다.

---

## 1. 오늘 당장 할 수 있는 것 — 키 없이 시작 (30분)

승인을 기다리지 않고 바로 실데이터로 갈 수 있습니다. CSV 로요.

```bash
cp .env.example .env          # 값은 아직 안 채워도 됩니다
```

`data/manual/oliveyoung.csv` 를 엑셀이나 구글시트로 열어 실제 상품·가격을 채웁니다.
파일 이름이 곧 판매처 코드입니다 (`oliveyoung.csv` → 올리브영).

```bash
npm run sync:catalog -- --dry   # 연습: 저장하지 않고 결과만 확인
npm run sync:catalog            # 실제 저장
npm run catalog:status          # 지금 무엇을 쓰고 있는지
npm start
```

CSV 의 `url` 열에 **상품 페이지 주소**를 넣으면 구매 버튼이 검색 결과가 아니라
그 상품 페이지로 직접 갑니다(추적 파라미터는 자동으로 붙습니다).
검색으로 보내면 사용자가 엉뚱한 상품을 사고, 그건 실적으로도 잡히지 않습니다.
비워두면 검색 딥링크로 대체됩니다.

서버 시작 로그가 `샘플 카탈로그` 에서 `실데이터` 로 바뀌면 성공입니다.

**이 단계만으로도 서비스는 굴러갑니다.** 상품이 20~50개 수준이면 CSV 주 1회 갱신이
API 연동보다 오히려 빠르고 정확합니다. API 는 상품이 수백 개로 늘 때 필요해집니다.

## 2. 네이버 쇼핑 — 가장 먼저 붙이세요 (당일 발급)

가입 즉시 키가 나오고, 하루 25,000회로 넉넉합니다. 가격 비교의 기준선으로 쓰기 좋습니다.

1. [developers.naver.com](https://developers.naver.com/) 로그인
2. **애플리케이션 등록** → 사용 API 에서 **검색** 선택 → 서비스 환경 **WEB** 선택
3. 발급된 **Client ID / Client Secret** 을 `.env` 에 붙여넣기

```bash
NAVER_CLIENT_ID=발급받은값
NAVER_CLIENT_SECRET=발급받은값
```

```bash
npm run catalog:check        # 키가 살아있는지 1회 호출로 확인
npm run sync:catalog
```

> 주의: 이 API 는 **검색 결과만** 줍니다. 네이버에서 수수료를 받으려면 제휴 프로그램에
> 따로 가입해야 하고, 그건 링크에 추적 파라미터를 붙이는 방식입니다.

---

## 3. 쿠팡 파트너스 — 심사가 있고, 한도가 빡빡합니다 (며칠~2주)

1. [partners.coupang.com](https://partners.coupang.com/) 가입 → 심사
2. 승인 후 로그인 → 상단 **Tools → 파트너스 API** 에서 키 발급
3. `.env` 에 `COUPANG_ACCESS_KEY` / `COUPANG_SECRET_KEY` / `COUPANG_PARTNER_ID`

> ⚠ **가장 중요한 제약**: 상품 검색 API 는 **1시간에 10회, 1회당 최대 10개**입니다.
> 그래서 사용자가 화면을 열 때마다 부르는 건 불가능합니다.
> 이 앱이 카탈로그를 파일로 들고 미리 동기화하는 이유가 이것입니다.
> 상품이 20개면 한 번 도는 데 두 시간이 걸립니다 — 동기화 스크립트가 알아서 나눠 돌립니다.

## 4. 올리브영·11번가 등 — 공개 API 가 없는 곳

올리브영은 공개 상품 API 를 제공하지 않습니다. 이런 판매처는 보통
제휴 네트워크(링크프라이스 같은 곳)를 통해 **링크만** 받고, 가격은 직접 넣습니다.

→ 1단계의 CSV 방식 그대로 쓰면 됩니다. 받은 추적 ID 는 `.env` 의
`OLIVEYOUNG_PARTNER_ID` 에 넣으면 링크에 자동으로 붙습니다.

## 5. Amazon — 나중에 (조건이 있습니다)

어소시에이트 계정을 만든 뒤 **180일 안에 적격 판매 3건**이 있어야 PA-API 키가 열립니다.
해외 상품이 필요해질 때 열면 됩니다. 키를 넣으면 어댑터는 이미 준비돼 있습니다.

---

## 6. 수수료율 입력 (5분, 하지만 빼먹으면 랭킹이 이상해집니다)

`data/commission-rates.json` 에 각 프로그램의 요율표를 보고 적습니다.

```json
{ "coupang": { "default": 0.03 },
  "naver":   { "default": 0.025 },
  "amazon":  { "default": 0.04, "cushion": 0.08 } }
```

값은 비율입니다(`0.03` = 3%). 이 숫자는 랭킹의 '수익 기여' 항에 쓰이지만
**적합도로 감쇠되므로**, 여기를 올린다고 내 피부에 안 맞는 상품이 1위가 되지는 않습니다.

## 7. 자동으로 돌게 하기

```bash
# 매일 새벽 4시 동기화 (crontab -e)
0 4 * * * cd /경로/Yes && /usr/bin/node scripts/sync-catalog.mjs >> /var/log/skinlab-sync.log 2>&1
```

동기화가 멈추면 `npm run catalog:status` 가 `N시간 전 데이터` 라고 알려주고,
48시간이 넘으면 서버 로그에도 경고가 찍힙니다. **오래된 가격은 환불 사유가 됩니다.**

---

## 8. 안전장치 (이미 들어가 있습니다)

- **한 판매처가 실패해도** 나머지는 정상 동기화되고, 실패한 곳은 **직전 가격을 유지**합니다.
  (전부 날리면 그 판매처 매출이 그날 0이 됩니다.)
- **검증에 실패한 결과는 저장하지 않습니다.** 가격이 0이거나 수수료율이 350%처럼
  말이 안 되면 저장을 거부하고 어제 데이터를 지킵니다.
- 실데이터가 없으면 자동으로 샘플 카탈로그로 돌아갑니다. 앱이 멈추지 않습니다.

## 9. 문제 해결

| 증상 | 원인 / 조치 |
|---|---|
| `키가 없어 건너뜁니다` | `.env` 에 값이 없거나 서버를 재시작하지 않음 |
| 쿠팡 401 / 403 | 서명 시각이 어긋남. 서버 시계(UTC) 확인 |
| 쿠팡 429 | 시간당 10회 초과. 다음 시간에 자동 재개 |
| 네이버 401 | Client ID/Secret 오타, 또는 '검색' API 미선택 |
| `검증 실패` 후 저장 안 됨 | 출력된 문제 목록 확인. 대개 CSV 가격 열이 비었거나 판매처 코드 오타 |
| 상품이 엉뚱하게 잡힘 | `data/curation.json` 의 `query` 를 더 정확하게. 예: `"아누아 어성초 77% 토너 250ml"` |
| 같은 상품이 둘로 갈림 | 해당 항목에 `aliases` 추가 |

## 10. 마지막 — 확인하고 쓰세요

각 어댑터의 **엔드포인트 주소와 서명 형식**은 공식 문서와 한 번 대조하고 쓰시길 권합니다.
이런 건 예고 없이 바뀌고, 이 문서는 작성 시점의 정보입니다.
바뀌더라도 고칠 곳은 `server/feeds/<판매처>.js` **한 파일**이고,
앱의 나머지(랭킹·화면·상담)는 손댈 일이 없도록 분리해 두었습니다.

- 쿠팡: [developers.coupang.com](https://developers.coupang.com/)
- 네이버: [developers.naver.com/docs/serviceapi/search/shopping](https://developers.naver.com/docs/serviceapi/search/shopping/shopping.md)
- Amazon: [webservices.amazon.com/paapi5/documentation](https://webservices.amazon.com/paapi5/documentation/)

그리고 제휴 링크에는 **수수료를 받는다는 고지**가 법적으로 필요합니다.
현재 추천 화면 하단과 각 상품 카드에 이미 노출돼 있습니다 — 지우지 마세요.
