# SkinLab AI — AI 닥터 상담형 피부 진단 · 전후 비교 · 커머스 수익화 앱

문진 6문항을 받고 카메라로 얼굴을 촬영하면, **브라우저 안에서** 피부를 9개 지표로 분석한 뒤
AI 상담 캐릭터 **닥터 세라**가 진료 흐름 그대로 짚어줍니다.
4주 뒤 재촬영하면 **전·후 사진 슬라이더**로 무엇이 실제로 달라졌는지 확인합니다.
간단한 소견은 무료로, 원인 분석·관리 순서·4주 플랜은 결제 후에 제공합니다.
그리고 측정된 피부톤(ITA°)·언더톤·고민 지표에 맞춰 화장품을 추천하고,
쿠팡 / 올리브영 / 네이버 / 11번가 / Amazon 오퍼를 **한 화면에서 랭킹·비교**해 구매로 연결합니다.

```bash
npm start          # http://localhost:8787
npm run check:deploy # 배포 전 설정 점검 (초보자용)
npm run backup       # 회원 기록 백업 (하루 한 번 예약 권장)
npm test           # 58개 테스트 (분석 엔진 + 상담 + API + 피드 + 보안)
npm run simulate   # 실사용 리허설 5개 페르소나 × 전체 여정 (91개 검사)
npm run build:demo # 서버 없이 도는 단일 파일 데모 (dist/demo.html)
npm run audit:mobile # 5개 기기 폭 × 8개 화면 모바일 감사
npm run setup:sim    # 시뮬레이션에 필요한 브라우저 도구 설치 (최초 1회)
npm run sim:verify   # 체험 샘플이 의도한 상태를 실제로 만드는지 검증
npm run catalog:status  # 지금 샘플/실데이터 중 무엇을 쓰는지
npm run catalog:check   # 판매처 API 키가 살아있는지 확인
npm run sync:catalog    # 판매처 데이터 동기화 (--dry 로 연습)
```
의존성 0개 — Node 20+ 내장 모듈만 사용합니다.

## 1. 무엇이 어떻게 측정되는가

이미지를 sRGB → **CIE Lab** 으로 옮긴 뒤, 얼굴 존별로 계산합니다.

| 지표 | 계산 방식 |
|---|---|
| 피부톤 | 피부 픽셀 평균 Lab → **ITA°** → Fitzpatrick I~VI, a\*/b\* 비율로 언더톤 |
| 톤 균일도 | 피부 L\* 표준편차 |
| 홍조·민감도 | a\* 상위 95퍼센타일 − 평균 |
| 유분 밸런스 | T존(이마·코) 정반사 픽셀 비율 vs U존 |
| 모공·피부결 | 코·볼 라플라시안 에너지 90퍼센타일 |
| 색소침착 | 국소 중앙값 대비 어두운(그리고 b\*가 높은) 픽셀 면적비 |
| 다크서클 | 눈밑 존 L\* vs 볼 L\* 차이 |
| 주름·탄력 | 눈가·이마의 세로 방향 그래디언트 우세도 |
| 수분·투명도 | 결 거칠기 + 유분 부족 + 톤 편차 복합 추정 |

- 얼굴 검출은 브라우저 `FaceDetector` 가 있으면 사용하고, 없으면 촬영 가이드 타원을 씁니다.
- 피부 픽셀은 YCbCr + HSV + RGB 세 규칙 중 **2개 이상** 만족해야 통과합니다(머리카락·배경 배제).
- 촬영 전 **품질 게이트**(밝기 / 초점 / 얼굴 크기)가 먼저 걸러 재촬영을 유도합니다.

**톤 보정(베버의 법칙)**: 결·주름·다크서클은 ΔL 로 재는데, 같은 요철이라도 어두운 피부에서는 ΔL 이 작게 나옵니다.
절대값으로 채점하면 짙은 톤일수록 점수가 부풀어 "손댈 게 없습니다"라는 잘못된 결론이 나오므로,
지각 대비(ΔL/L)를 기준 밝기 L\*65 로 환산해 채점합니다. 피부 픽셀 판정의 밝기 하한도 이미지 평균에서 역산합니다
— 고정하면 Fitzpatrick V~VI 가 실내 조명에서 통째로 '피부 아님'으로 떨어집니다.

> 참고용 정보이며 의료기기·의학적 진단이 아닙니다. UI에 항상 고지됩니다.

## 1-A. AI 닥터 "닥터 세라"

실제 진료 흐름을 그대로 따라갑니다: **문진 확인 → 불일치 지적 → 시진 소견 → 종합 소견 → 관리 순서 → 주의 → 재진 예약**.

가장 큰 값은 **자각과 측정이 어긋나는 지점**을 짚는 단계입니다.
"건성이라고 하셨는데 T존 광택이 28%입니다. 수분 부족을 유분으로 보상하는 상태라, 유분 잡는 제품을 쓰면 더 나빠집니다."
— 흔한 오판이고, 실제로 고객이 가장 크게 반응하는 대목입니다.

- 기본 엔진은 **규칙 기반**(`public/js/engine/consult.js`)입니다. 키 없이, 오프라인에서, 지연 없이 항상 같은 품질로 나오고 무엇을 말할지 전부 추적 가능합니다.
- `ANTHROPIC_API_KEY` 가 있으면 `server/doctor.js` 가 그 대본을 Claude(`claude-opus-5`)로 **문장만** 다듬습니다.
  모델이 수치·순서·성분을 바꾸면(길이·stage 불일치) 통째로 버리고 규칙 대본으로 되돌아갑니다 — 지어낸 숫자는 곧 의료 오정보이기 때문입니다.
- SDK는 **optionalDependency** 입니다. 설치하지 않아도 앱은 그대로 동작합니다.

### 표현 규칙 (중요)

'진단·처방·치료' 대신 **'소견·관리·제안'** 을 씁니다. 캐릭터는 화면에서 *AI 가상 캐릭터 · 의료 행위가 아님* 을 항상 고지합니다.
한국에서 진단·처방을 표방하면 의료기기 인허가 대상이 되고, "전문의보다 낫다"류의 비교 표현은 표시광고법 위반이자 앱 심사 리젝 사유입니다.
체감은 상담처럼, 표기는 관리 가이드로 설계했습니다.

## 1-B. 전 / 후 사진 비교

- 촬영본은 **IndexedDB(기기 안)** 에만 저장됩니다(`public/js/storage.js`, 최대 24장, 오래된 것부터 정리).
- 비교 화면은 `clip-path` 슬라이더로 두 장을 겹쳐 보여주고, 최근 측정에서 70점 미만인 부위에 **마커**를 얹습니다.
- 항목별 전/후 점수 변화(▲▼/유지)와 **닥터의 재진 소견**(무엇이 반응했고 무엇이 내려갔는지)을 함께 냅니다.
- 14일 미만 간격이면 "turnover 주기가 28일이라 지금 차이는 조명·컨디션 영향일 수 있다"고 먼저 말합니다.

## 2. 프라이버시 — 사진은 서버로 가지 않습니다

분석은 전부 브라우저에서 끝나고, 서버로는 **숫자 지표와 문진 선택지만** 전송됩니다.
`POST /api/analysis` 의 본문에 이미지·픽셀 데이터가 포함되는 경로는 없습니다.
전/후 비교용 사진도 IndexedDB에만 남으므로, 다른 기기나 시크릿 모드에서는 보이지 않습니다(화면에 그렇게 안내합니다).
회원가입 없이 익명 서명 토큰으로 시작해 이탈을 줄입니다.

## 3. 수익화 구조

| 축 | 내용 |
|---|---|
| 리포트 언락 | ₩4,900 / 1회 (7일 열람) |
| 월간 멤버십 | ₩9,900 — 무제한 진단, 변화 추적, 리마인더, 광고 제거 |
| 연간 멤버십 | ₩79,000 — 2개월분 무료 |
| 제휴 커머스 | 판매처별 수수료(2.8~8%) · 클릭→전환 포스트백으로 확정 |
| 객단가 상승 | 진단 기반 **4주 루틴 풀세트 번들**(묶음가 노출) |
| 재방문 | 4주 뒤 재측정 → 점수 변화 그래프 → 제품 교체 제안 |

**무료/유료 경계는 서버에서 강제**됩니다. 결제 전에는 잠긴 지표 값이 응답에 아예 포함되지 않습니다
(`server/index.js` 의 `buildReport`). 클라이언트 CSS로 가리는 방식이 아닙니다.

### 랭킹 공식 (`public/js/engine/ranking.js`)

```
총점 = 적합도 × 0.55 + (전환기대 × 0.30 + 수익기여 × 0.15) × (0.3 + 0.7 × 적합도)
```

상업 점수를 **적합도로 감쇠**시킵니다. 이렇게 하지 않으면 수수료율만 높은 비관련 상품이
1위로 올라오고, 추천 신뢰가 깨져 결국 재방문과 구독이 함께 줄어듭니다.
각 카드에는 순위 근거(`reasons`)와 제휴 고지를 함께 노출합니다.

판매처 오퍼는 가격 45% / 배송·신뢰 35% / 수익 기여로 정렬하고 **최저가 배지**를 항상 표시합니다.

## 6-0. 카메라 없이 체험하기 (앱 안 시뮬레이션)

홈 화면의 **「카메라 없이 체험하기」** 를 누르면 샘플 얼굴로 진단부터 상담·추천·전후 비교까지
그대로 돌아갑니다. 카메라 권한이 없거나 막힌 환경(아이프레임·데스크톱)에서도 전 기능을 볼 수 있고,
데모나 투자 미팅에서 바로 보여줄 수 있습니다.

- 샘플 얼굴은 **캔버스에 직접 그립니다**(`public/js/sim/faces.js`). 실제 인물 사진을 쓰지 않습니다.
  결·잡티·T존 광택·볼 홍조·눈밑 그늘을 각각 조절해 원하는 상태를 만듭니다.
- 페르소나 5종: 20대 지성 / 30대 자각불일치 / 40대 색소 / 민감성 / 딥 스킨톤.
- **4주 뒤 재측정까지 함께 생성**해 전·후 비교를 즉시 볼 수 있습니다(기준선은 28일 전으로 기록).
- 체험 기록은 **`체험` 배지**가 붙고 **매출·퍼널 지표에서 제외**됩니다. 섞이면 전환율이 거짓말을 합니다.

`npm run sim:verify` 는 각 샘플이 선언한 상태를 실제로 만들어내는지 검사합니다
(예: '지성' 샘플의 1순위 고민이 정말 유분인지, 4주 뒤 개선이 +8점 이상 보이는지).
샘플을 손보다 조용히 어긋나는 걸 막습니다.

> 이 검증을 만들면서 실제로 잡은 것: 홍조 샘플이 아무것도 그리지 않고 있었습니다(편집 실패).
> 그 상태로는 "민감성 사용자가 홍조 100점"이라 지표가 고장난 것처럼 보였는데,
> 샘플을 고치자 100 → 92 → 60 → 8 로 정확히 반응했습니다. 지표는 정상이었습니다.

## 6-A. 실사용 리허설 (`npm run simulate`)

단위 테스트가 함수를 잠근다면, 이 스크립트는 사람이 실제로 밟는 경로를 통째로 돕니다.
5개 페르소나(20대 지성 / 30대 자각 불일치 / 40대 색소 / 10대 문진 스킵 / 딥 스킨톤)로
문진 → 촬영 → 상담 → 결제 → 추천 → 제휴 클릭 → 재측정 → 전후 비교까지 밟고,
엣지 케이스(어두운 사진, 1회권 재사용, 잘못된 쿠폰, 측정 전 진입)와 서버 매출 집계까지 검증합니다.

`SIM_SHOTS=1` 로 단계별 스크린샷을 남깁니다. 이 리허설이 실제로 잡아낸 결함:

| 발견 | 조치 |
|---|---|
| Fitzpatrick VI 가 실내 조명에서 미검출 | 밝기 하한을 이미지 평균에서 역산 (`adaptiveFloors`) |
| 짙은 톤일수록 총점이 부풀어 오름 | ΔL 지표에 베버 보정 적용 |
| 딥 톤에 0% 매칭 호수를 "추천"으로 노출 | 셰이드 커버리지 확장 + 미커버 시 매칭 대신 경고 표시, 랭킹 강등 |
| 무료 상담의 핵심 후크가 5초 뒤에 등장 | 타이핑 속도 조정, 재생 완료 상태를 DOM 에 노출 |

## 6-B. 단일 파일 데모 (`npm run build:demo`)

`dist/demo.html` 하나만 열면 서버 없이 전 기능이 돕니다. 링크로 공유하거나 오프라인에서 시연할 때 씁니다.

- ES 모듈들을 의존성 순서로 이어붙이고 import/export 를 제거해 인라인 모듈 하나로 만듭니다(최상위 이름 충돌은 빌드 시 에러).
- 서버가 하던 권한 게이팅·결제·랭킹은 `scripts/demo-runtime.js` 가 브라우저에서 대신합니다. **결제는 모의 결제이고 실제 청구되지 않습니다.**
- 운영 빌드로 쓰면 안 됩니다 — 무료/유료 경계가 클라이언트에 있어 우회 가능합니다. 그 경계는 서버(`server/index.js`)에서만 강제해야 합니다.

## 6-C. 모바일 감사 (`npm run audit:mobile`)

"모바일 우선"은 `max-width` 를 걸었다는 뜻이 아닙니다. 실제 기기 폭(320 / 360 / 375 / 393 / 430)에서
화면마다 다음을 검사합니다 — 가로 스크롤, 44px 미만 탭 영역, 16px 미만 입력창(iOS 포커스 확대),
뷰포트를 벗어난 요소(가로 스크롤 컨테이너는 제외), 상자 밖으로 넘친 내용, 콘솔 에러.

첫 실행에서 34종이 나왔고 지금은 0종입니다. 이 감사가 잡아낸 것:

| 발견 | 조치 |
|---|---|
| 같은 사진 재선택 시 앱이 반응하지 않음 | 처리 후 `input.value` 를 비워 `change` 가 다시 뜨게 |
| 탭바·뒤로가기·문진 선택지가 33~40px | 44~48px 로 확대 (HIG 44pt / 머티리얼 48dp) |
| 쿠폰 입력·비교 셀렉트가 12~13px | 16px — iOS 는 그 미만에서 화면을 확대하고 되돌리지 않음 |
| 토스트가 셔터·구매 버튼을 가림 | 상단으로 이동 |
| 카메라 오류를 `NotFoundError` 로 노출 | 원인별 안내 + 제약 완화 재시도 + 주 동작을 ‘사진 · 앨범’으로 전환 |

노치/홈 인디케이터 안전영역, `100dvh`, `touch-action:manipulation`, 짧은 화면·가로 모드,
apple-touch-icon 과 홈 화면 추가 메타도 함께 넣었습니다.

## 6-D. 판매처 실데이터 연동 (`npm run sync:catalog`)

샘플 카탈로그를 실제 판매처 데이터로 바꾸는 층입니다. 자세한 절차는
**[docs/파트너-API-연동.md](docs/파트너-API-연동.md)** 에 초보자 기준으로 적어두었습니다.

```
data/curation.json      무엇을 팔지 + 피부 매칭 태그 + 셰이드  ← 사람이 정하는 부분
data/commission-rates.json  프로그램별 수수료율             ← 요율표 보고 입력
data/manual/*.csv       공개 API 가 없는 판매처(올리브영 등)   ← 엑셀로 편집
server/feeds/*.js       판매처별 어댑터 (쿠팡·네이버·Amazon)
data/catalog.live.json  동기화 결과 (커밋 안 함)
```

- **API 가 주지 않는 것**: 피부 타입·고민 매칭과 셰이드 ITA 값. 이건 `curation.json` 에 사람이 씁니다.
  가격은 누구나 긁을 수 있지만 이 매칭은 못 베낍니다 — 이 앱의 실제 자산입니다.
- **쿠팡 검색 API 는 1시간 10회, 1회 10개** 제한이라 사용자 요청마다 부를 수 없습니다.
  그래서 미리 동기화해 파일로 들고 있습니다.
- 한 판매처가 실패해도 나머지는 살리고, 실패한 곳은 **직전 가격을 유지**합니다.
- 검증에 실패한 결과는 **저장하지 않습니다**. 깨진 카탈로그보다 어제 데이터가 낫습니다.
- 실데이터가 없거나 48시간 이상 낡으면 서버 로그와 `/api/config` 가 알려줍니다.

## 6-E. 보안 (`tests/security.test.js`)

출시 전 점검에서 실제로 나온 것들과 그 조치입니다. 전부 회귀 테스트로 잠갔습니다.

| 심각도 | 발견 | 조치 |
|---|---|---|
| 높음 | `GET /%` 한 번으로 **서버 프로세스가 종료**됐습니다. 인증 없이 누구나 서비스를 내릴 수 있었습니다 | 요청 처리 전체를 감싸고, 잘못된 인코딩은 400 으로 응답 |
| 높음 | 운영 환경에서 기본값(`SKINLAB_PAYMENTS=mock`, 기본 서명 키, `ADMIN_TOKEN` 없음)으로 조용히 기동 — 무료 결제·토큰 위조·지표 노출 | `NODE_ENV=production` 이면 **기동을 거부**하고 무엇이 문제인지 출력 |
| 중간 | 경로에 `..` 가 있으면 정규화 뒤 흔적이 사라져 SPA 폴백으로 200 | 정규화 전에 `..` 세그먼트를 403 으로 차단, 경로 봉쇄를 `resolve` + 구분자 기준으로 |
| 중간 | 브라우저가 계산한 분석값을 **그대로 저장·재전송** — 지표 이름표에 문자열 주입, 점수 오염 | `server/validate.js` 에서 아는 키만 통과, 이름표는 서버 정본으로 교체, 숫자는 범위로 절단 |
| 중간 | `METRIC_SPEC['__proto__']` 가 truthy 라 프로토타입 체인 키가 검증을 통과 | 검증 표를 `Object.create(null)` 기반으로 |
| 중간 | 호출 제한 없음 — 분석·세션·클릭 무한 생성 가능(DB 팽창, 제휴 실적 오염) | IP·경로별 시간당 한도, 초과 시 429 + `Retry-After` |
| 중간 | 지표가 일부만 오면 진단이 500 | 없는 지표를 중립값으로 처리 |
| 낮음 | 관리자·포스트백 토큰을 `!==` 로 비교 (타이밍 차이) | `timingSafeEqual` |
| 낮음 | 프리플라이트가 `Access-Control-Allow-Origin: *` 를 광고 | 기본 동일 출처, 필요하면 `CORS_ORIGIN` 으로 명시 |
| 낮음 | 서버 오류 문자열을 `innerHTML` 로 렌더 | `textContent` 로 |

확인된 안전 사항: 얼굴 사진은 서버로 전송되지 않고, 무료/유료 경계는 서버에서 강제되며,
남의 리포트는 403, 1회 이용권은 결제한 리포트에만 적용됩니다.

## 6-F. 진짜 홈페이지로 띄우기

**[docs/홈페이지-띄우기.md](docs/홈페이지-띄우기.md)** — 개발 경험이 없는 사람 기준으로 쓴 배포 가이드입니다.
터미널 명령 없이 웹에서 버튼만 눌러 배포합니다.

- `render.yaml` — 저장소만 연결하면 서버 사양·디스크·헬스체크·자동배포가 자동 설정됩니다
- `Dockerfile` — 다른 플랫폼(Fly.io, Cloudtype 등)이나 직접 서버에 올릴 때
- `npm run check:deploy` — 무엇이 비었고 그래서 무슨 일이 생기는지 알려줍니다

**결제 없이 시작하는 길**: 국내에서 유료 결제를 받으려면 사업자등록이 필요합니다(결제대행사가 개인과 계약하지 않습니다).
`SKINLAB_PAYMENTS=none` 으로 두면 리포트를 전부 무료로 열고 **제휴 커머스 수익만** 받습니다.
사업자등록을 마친 뒤 이 값만 `toss` 로 바꾸면 유료 전환이 끝납니다 — 코드는 그대로입니다.

## 6-G. 실사용 준비 (진짜 사용자를 받기 전)

배포가 끝나도 **사용자를 받으려면** 세 가지가 더 필요했습니다. 전부 구현돼 있습니다.

### 계정 이어받기 (복구 코드)
회원가입이 없어 브라우저 토큰 하나로 사람을 구분합니다. 이탈을 줄이는 설계지만,
**브라우저 기록을 지우거나 폰을 바꾸면 4주간 쌓은 기록과 결제한 이용권이 영영 사라집니다.**
기록 화면 → 내 데이터에서 복구 코드를 발급받아 다른 기기에서 이어받을 수 있습니다.

- 코드는 서버에 **해시로만** 저장합니다 — DB 가 유출돼도 계정을 열 수 없습니다
- 새로 만들면 이전 코드는 즉시 무효
- 입력 시도는 시간당 8회로 제한 (무차별 대입 차단)

### 내 데이터 삭제
개인정보보호법상 파기 요구에 응할 수 있어야 하고, 무엇보다 **지울 수 있다는 걸 알아야 얼굴을 찍습니다.**
서버 기록·문진·복구 코드가 즉시 지워지고 기기의 사진도 함께 삭제됩니다.
결제 기록은 법령상 보관 의무가 있어 **금액과 시각만 남기고 사람과의 연결을 끊습니다.**

### 약관·개인정보처리방침 (`public/legal.html`)
이 앱이 **실제로 하는 동작**에 맞춰 작성했습니다 — 무엇을 저장하고 무엇을 저장하지 않는지,
얼굴 사진이 전송되지 않는다는 점, 제3자(판매처·결제사·선택적 Anthropic API)에 무엇이 전달되는지.
`[[대괄호]]` 부분만 채우면 됩니다. `npm run check:deploy` 가 채우지 않은 칸을 잡아줍니다.

### 그 밖의 안전장치
- 결제·이용권은 **즉시 디스크에 기록**합니다. 기본 저장은 120ms 지연이라 그 사이 서버가 죽으면 결제가 사라집니다.
- `npm run backup` — 회원 기록은 파일 하나뿐입니다. 손상된 파일은 백업하지 않고 거부합니다.

## 7. 운영 전 반드시 할 일

1. `data/products.json` 은 **샘플 시드**입니다. → **[docs/파트너-API-연동.md](docs/파트너-API-연동.md)** 를 따라 실데이터로 교체하세요.
   키 없이 CSV 만으로 오늘 시작할 수 있고, 네이버(당일 발급) → 쿠팡(심사) 순으로 붙이면 됩니다.
2. `SKINLAB_SECRET` / `ADMIN_TOKEN` 교체, HTTPS 종단 적용.
   `NODE_ENV=production` 으로 띄우면 이 값들이 없을 때 서버가 기동을 거부합니다.
   호출 제한은 프로세스 메모리 기반이라 인스턴스를 여러 대 띄우면 앞단(nginx/CDN)에서도 걸어야 합니다.
3. JSON 스토어 → RDB 전환 (`server/store.js` 인터페이스 유지).
4. 각 제휴 프로그램 약관에 맞는 고지 문구 확인 (현재 랭킹 근거 + 수수료 고지 노출 중).
5. 촬영 데이터 처리 방침·의료기기 아님 고지를 앱스토어 심사 기준에 맞게 재검토.
6. 닥터 캐릭터 문구를 법무 검토에 올릴 것 — 의료 표현 금지 규칙은 코드(테스트 `상담문에 의료 표현을 쓰지 않는다`)로 잠가뒀지만, 마케팅 카피는 코드 밖에 있습니다.
