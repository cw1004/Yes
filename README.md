## 🧠 AI 추천 종목 3선 (`/ai.html`)

“월가와 전세계 정보를 분석해 3종목을 골라 달라”는 요구를 이렇게 구현했습니다.

### 동작 방식

```
1) 지표 스크리닝    유니버스(미국 27 / 한국 12종목)를 신호 엔진으로 전수 계산
                    → 추세·모멘텀·거래량·변동성 상위 10개를 후보로 추림
2) 정보 수집        글로벌 금융 RSS 9개 + 종목별 헤드라인을 모아 중복 제거
                    CNBC · MarketWatch · Nasdaq · Investing.com · FT · 한국경제 · 머니투데이 …
3) 모델 분석        사용 가능한 AI 엔진에 같은 후보·같은 뉴스를 주고 각자 3종목을 받음
                    Claude 는 여기에 더해 서버측 웹 검색으로 직접 조사
4) 합의 계산        여러 엔진이 겹쳐 고른 종목을 우선. 한 엔진만 고른 종목은 그렇게 표시
5) 성과 기록        추천 시점 가격과 함께 저장 → 나중에 실제 가격으로 채점
```

### ⚡ 실시간 단타 후보 스캐너

`/ai.html` 아래쪽 **실시간 단타 후보** 패널은 AI 호출 없이(=요금 없이) 계속 돕니다.
미국·한국 유니버스를 각각 20초 / 15초 주기로 다시 훑어 **지금 단타를 하기 좋은 순서**로 정렬합니다.

여기서 매기는 점수는 신호 엔진의 방향 점수(-100~+100)가 아니라 **단타 적합도(0~100)** 입니다.
방향이 맞아도 거래가 얇거나 스프레드가 비싸면 단타로는 돈이 안 되기 때문입니다.

| 항목 | 배점 | 보는 것 |
| --- | --- | --- |
| 유동성 | 25 | 거래량이 평소의 몇 배인가 (체결이 되는가) |
| 변동성 | 25 | ATR%가 단타 스위트스팟인가 — 미국 0.35~1.6%, 한국 0.5~2.2%. **과열이면 감점** |
| 비용 대비 기대폭 | 20 | 한국: 목표 호가 − 본전 호가 / 미국: 손익비 |
| 지금 움직이는가 | 20 | 직전 스캔 대비 점수·가격 변화 |
| 방향의 선명함 | 10 | 신호 점수의 절댓값 (매수든 매도든) |

등급은 **A**(75+, 지금 바로 볼 만함) · **B**(60+, 괜찮음) · **C**(45+, 지켜보기) · **D**(그 이하, 부적합)이고,
직전 스캔에 없다가 새로 올라온 종목에는 `NEW` 가 붙습니다. 행을 누르면 해당 차트로 바로 이동합니다.

- 스캐너는 **화면을 보는 사람이 있을 때만** 돕니다 (구독이 끊기고 1분 뒤 자동 정지).
- `자동 스캔` 체크를 끄면 SSE 연결을 닫고 마지막 결과만 남습니다.
- 한 종목이 실패해도 나머지로 계속 진행하고, 스캔 자체가 실패하면 사유만 남기고 다음 주기에 다시 시도합니다.

### 🦙 Meta AI(Llama) 연동

**meta.ai 자체에는 공개 API가 없습니다.** 그 화면은 소비자용 채팅 서비스라 프로그램이 붙을 자리가
없습니다. Meta 모델을 쓰는 방법은 **Llama 를 OpenAI 호환 엔드포인트로 부르는 것**이고,
이 앱은 그 방식으로 붙습니다. 아래 셋 중 아무 데나 연결됩니다.

| 방식 | 설정 | 비고 |
| --- | --- | --- |
| 로컬 Ollama | `LLAMA_BASE_URL=http://localhost:11434/v1` | API 키 불필요, `ollama pull llama3.1` |
| Meta Llama API | `LLAMA_BASE_URL=https://api.llama.com/compat/v1` + `LLAMA_API_KEY` | 모델명은 발급 콘솔 확인 |
| Groq · Together 등 | 각 서비스의 OpenAI 호환 주소 + `LLAMA_API_KEY` | 모델명은 서비스마다 다름 |

```bash
export LLAMA_BASE_URL=http://localhost:11434/v1
export LLAMA_MODEL=llama3.1
```

로컬 주소는 키 없이 허용하되 **실제로 응답하는지 두드려 보고** 켭니다(꺼져 있으면 화면에
`연결 실패`로 표시). 원격 주소는 키가 있어야 켜집니다.

**두 엔진을 함께 켜면** 같은 후보·같은 뉴스를 각자 판단하고, 화면에서 결과를 비교합니다.

- 둘 다 고른 종목 → `✓ 2개 엔진 합의` (순위 1위로 올라감)
- 한쪽만 고른 종목 → `Claude만 선택 (1/2)` 처럼 표시
- `엔진별 의견 비교`를 펼치면 두 모델의 논지·신뢰도를 나란히 볼 수 있습니다

한쪽 엔진이 실패해도 나머지로 진행하고, 실패 사유를 화면에 남깁니다.

### AI가 지어내지 못하게 막은 장치

- 종목은 **반드시 후보 목록 안에서** 고르게 합니다. 목록 밖 심볼이 오면 `후보 목록 밖 · 지표 미검증` 경고가 붙습니다.
- 화면의 **가격·RSI·거래량 배율·진입/손절/목표는 전부 우리 엔진이 계산한 값**입니다. AI가 쓴 숫자를 그대로 보여주지 않습니다.
- 근거는 **제공된 뉴스 목록이나 검색 결과에서 확인한 것만** 쓰게 하고, 종목마다 출처 URL을 남기게 했습니다.
- 웹 검색이 없는 모델(Llama)에는 "당신에게는 검색 기능이 없으니 목록에 없는 내용은 쓸 수 없다"고 명시합니다.
- AI가 고른 종목의 기술적 점수가 매도 신호(-20 이하)면 `⚠ 지표는 매도 신호` 배지를 띄웁니다.
- 화면에 출력되는 모든 문장은 이스케이프하고, 출처 링크는 **http(s) 스킴만** 허용합니다.

### 📊 성과 추적 — "수익 최대화"에 대한 정직한 답

정보원을 늘린다고 수익이 늘지는 않습니다. **맞았는지 측정해야** 개선할 수 있습니다.
추천이 나올 때마다 그 시점 가격·목표가·손절가를 함께 저장하고, 이후 실제 가격으로 자동 채점합니다.

- 목표가 도달 / 손절가 이탈 / 기간 만료(당일 8h, 2~3일 72h, 1~2주 336h)를 구분
- 누적 승률, 평균 수익률, 최고·최저
- **엔진별 성적**(Claude vs Llama vs 지표 전용), 신뢰도별, 시장별 성적
- 표본이 20건 미만이면 "통계적으로 의미 없다"고 화면에 경고

기록은 `logs/ai-picks.jsonl` 에 남습니다.

> ⚠️ 이것은 과거 추천을 사후 채점한 것이지 백테스트가 아닙니다. 그리고 **어떤 시스템도 수익을
> 보장하지 못합니다.** AI가 최신 뉴스를 읽어도 미래를 알 수는 없고, 뉴스는 이미 가격에 반영되어
> 있는 경우가 많습니다. 이 화면은 참고 자료이며 투자 권유가 아닙니다.

### 설정

```bash
npm install                        # @anthropic-ai/sdk (Claude 사용 시)
export ANTHROPIC_API_KEY=sk-ant-...    # Claude
export LLAMA_BASE_URL=http://localhost:11434/v1   # Llama (선택)
node server/server.js
```

엔진이 하나도 없어도 화면은 동작합니다. 이때는 **기술적 지표 상위 3종목**만 보여주며
`지표 전용 (AI 엔진 없음)`이라고 표시됩니다.

| 환경변수 | 기본값 | 설명 |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | — | Claude 엔진 |
| `ANTHROPIC_MODEL` | `claude-opus-5` | |
| `LLAMA_BASE_URL` | 키 있으면 Llama API, 없으면 `localhost:11434/v1` | OpenAI 호환 주소 |
| `LLAMA_MODEL` | `llama3.1` | 서비스마다 이름이 다름 |
| `LLAMA_API_KEY` | — | 원격 엔드포인트용 |
| `LLAMA_ENABLED` | — | `0` 이면 Llama 사용 안 함 |
| `NEWS_ENABLED` | — | `0` 이면 뉴스 수집 생략 |

| `AI_CACHE_TTL_MS` | `600000` | 같은 조건 재요청 캐시(10분) |

(Llama 를 로컬 Ollama 로 돌리면 그 부분은 무료입니다.)
화면 상단에 토큰 사용량과 예상 비용이 그대로 표시됩니다.

## 🎮 과거 장 재생 연습 (`/replay.html`)

설정을 검증하는 건 백테스트가 하지만, **손에 익히는 건 직접 해 봐야** 합니다.
지나간 장을 빨리감기로 틀어 놓고 매수·매도 버튼을 눌러 가며 연습합니다.

**진짜 연습이 되게 만든 것** (`server/replay.js`)

| 규칙 | 어떻게 |
| --- | --- |
| **미래를 서버가 쥔다** | 아직 오지 않은 봉은 응답에 담지 않는다. 개발자도구를 열어도 다음 봉을 볼 수 없다 |
| 보는 봉의 종가로 못 산다 | 버튼을 누르면 **다음 봉 시가**에 체결된다. 실제와 같다 |
| 슬리피지·실제 비용 | 1호가 밀림 + 수수료·거래세 원 미만 절사까지 |
| 채점은 비교로 | **그냥 사서 들고 있었을 때**와 나란히 보여 준다 |

마지막 항목이 핵심입니다. 벌었어도 그냥 들고 있는 것보다 못했다면 잘한 게 아닙니다.
채점표는 그 경우 *"그냥 사서 들고 있었다면 N원이었습니다 — 단타가 손해였습니다"* 라고 말하고,
비용이 수익보다 크면 *"거래를 줄이는 편이 낫습니다"* 라고 덧붙입니다.

세션은 서버 메모리에 2시간 보관되며, 진행할 봉이 60개 미만이면 시작하지 않습니다.

**키보드** — `Space` 한 봉 진행 · `B` 매수 · `S` 매도 · `P` 자동 재생

## 🔬 실전 준비 — 수익 구간 찾기와 실전 점검

### 수익 구간 탐색 (`/api/kr/optimize`)

"손절·목표를 얼마로 잡아야 돈이 되는가"를 과거 봉으로 **전수 조사**합니다.
손절 6단계 × 목표 6단계 × 진입점수 3단계 = 108개 조합을 모두 돌려
히트맵으로 보여 줍니다. 0.2초면 끝납니다(신호를 조합마다 다시 계산하지 않고 한 번만 계산).

**백테스트가 거짓말하지 못하게 막은 장치** (`server/backtest.js`)

| 규칙 | 왜 |
| --- | --- |
| 미래 봉을 보지 않는다 | `candles[0..i]` 만 넘긴다. 테스트로 강제 |
| 신호가 난 봉에 못 산다 | 봉이 닫힌 뒤 신호가 나오므로 **다음 봉 시가**에 체결 |
| 한 봉에서 손절·목표가 다 닿으면 **손절** | 봉 데이터로는 순서를 알 수 없다. 최악을 가정 |
| 슬리피지를 뗀다 | 매수는 위로, 매도는 아래로 1호가 |
| 실제 비용을 뗀다 | 수수료·거래세를 원 미만 절사까지 반영 |
| 표본을 밝힌다 | 30건 미만이면 `reliable: false` |

**과최적화를 막는 장치** (`server/optimize.js`)

108개를 돌려 1등을 고르면 그건 보통 **과거에 우연히 맞은 조합**입니다. 그래서:

1. 데이터를 앞 70%(학습) / 뒤 30%(검증)로 나눕니다.
2. 학습에서 좋았던 조합을 **검증 구간에서 다시** 돌립니다.
3. **양쪽 모두 기대값이 양수인 것만** "생존"으로 칩니다. 히트맵에서 흰 테두리로 표시됩니다.
4. 하나도 없으면 그렇게 말합니다 — *"어떤 설정으로도 안정적인 수익 구간이 확인되지 않았습니다."*

엔진이 제대로 도는지는 양방향으로 검증합니다: **추세가 있는 데이터에서는 찾아내고,
랜덤워크에서는 하나도 찾지 못해야** 합니다(둘 다 테스트로 고정).
비용을 물면서 무작위로 사고팔면 반드시 잃기 때문입니다.

> 히트맵 배색은 **빨강(손실) ↔ 회색(0) ↔ 파랑(수익)** 입니다.
> 빨강↔초록이 아닌 이유는 색각 이상에서 구별되지 않기 때문이고(검증 결과 protan ΔE 12.5 통과),
> 칸마다 숫자를 함께 찍어 색이 유일한 단서가 되지 않게 했습니다.

### 실전 점검 (`/api/kr/preflight`)

## ⏰ 거래 시간대 — 언제 하느냐도 무엇을 사느냐만큼 중요하다

단타는 **거래가 몰리는 시간**에만 유리합니다. 거래대금이 몰리면 스프레드가 좁고 체결이 잘 되며
추세가 이어집니다. 반대로 점심시간처럼 거래가 마르는 구간에서는 같은 전략이 슬리피지만 남깁니다.

앱은 두 시장의 구간을 알고 있고, 화면 상단에 **지금이 어떤 구간인지와 남은 시간**을 띄웁니다.

| KST | 시장 | 구간 | 등급 | 전략 |
| --- | --- | --- | --- | --- |
| 09:00~09:40 | 🇰🇷 | 시초가 폭풍 | **1순위** | 갭상승 2% 이내 + 5분봉 첫 양봉 + 거래량 급증 → 0.5~1% 스캘핑 |
| 10:00~11:00 | 🇰🇷 | 기관 1차 매매 | 보통 | 5분봉 20이평 추세 추종 |
| 11:30~13:30 | 🇰🇷 | 점심 공백 | ❌ 피함 | 쉬는 것이 전략 |
| 14:20~15:20 | 🇰🇷 | 마감 물량 사냥 | 양호 | 14:30 눌림목 지지 → 15:10 돌파 시 종가 베팅 |
| 21:00~22:30 | 🇺🇸 | 프리마켓 | 보통 | 갭이 아주 큰 종목의 되돌림만. 얇은 호가 주의 |
| 22:30~23:30 | 🇺🇸 | 오프닝 파워아워 | **1순위** | 첫 5분봉(09:30~09:35) 고가/저가 돌파 → 0.3~0.8% 스캘핑 |
| 01:00~02:30 | 🇺🇸 | 점심 공백 | ❌ 피함 | 쉬는 것이 전략 |
| 04:00~05:00 | 🇺🇸 | 클로징 파워아워 | 양호 | 15:00 눌림 확인 후 15:30 추세 추종 |

> 미국 구간은 **현지 시각으로 정의하고 KST 로 환산**합니다. 위 표는 서머타임(EDT) 기준이고,
> 겨울(EST)에는 한 시간씩 밀려 오프닝 파워아워가 KST 23:30~00:30 이 됩니다. 앱이 자동으로 계산합니다.

### 자동매매를 이 시간대에만 돌리기

한국 화면 자동매매 설정의 `거래 시간대`:

| 설정 | 동작 |
| --- | --- |
| `제한 없음` | 정규장 내내 (기본값) |
| `주요 구간만` | 점심 공백을 제외한 구간에서만 진입 |
| `골든타임만` | 09:00~09:40 시초가 구간에서만 진입 |

청산은 시간대와 무관하게 계속 동작합니다 — **들어간 포지션은 언제든 나올 수 있어야** 하기 때문입니다.

### 가정과 실측을 나란히

위 표의 구간·순위는 **일반적으로 알려진 시장 미시구조**를 옮긴 것입니다.
"개장 직후와 마감 직전에 거래가 몰리고 점심에 마른다"는 방향은 널리 확인된 사실이지만,
"거래대금의 40%" 같은 구체적 수치는 종목·시기마다 달라 그대로 믿을 값이 아닙니다.

그래서 앱은 이 표를 **가정**으로만 쓰고, 실시간 스캐너가 도는 동안 **10분 단위로 직접 측정**합니다
(`server/ai/daypart.js`). 며칠 쌓이면 `/ai.html` 의 `하루 계획표`에 사용자의 관심종목 기준
실제 시간대 곡선이 막대로 그려집니다. **가정과 실측이 다르면 실측이 맞습니다.**

## 🇰🇷 한국 초단타 (`/kr.html`)

한국투자증권 OpenAPI로 **10초 · 20초 · 30초 · 1분 · 3분 · 5분 · 10분봉**을 보고 매매합니다.
초봉(10·20·30초)은 KIS가 주지 않는 단위라 **실시간 체결틱을 받아 직접 만드는 봉**입니다.
그래서 접속한 순간부터 쌓이며, 지표가 나오려면 5분쯤 기다려야 합니다(1분봉 이상은 과거 조회로 즉시 채워집니다).

### 매매비용 — 오르고 팔아도 손해일 수 있다

초단타는 비용이 수익의 대부분을 갉아먹습니다. 그래서 앱은 비율로 어림하지 않고
**증권사가 실제로 정산하는 방식** 그대로 계산합니다 — 매수·매도 각각 **원 미만 절사**.

| 항목 | 기본값 | 비고 |
| --- | --- | --- |
| 수수료 (매수·매도 각각) | `0.0036396%` | 한국투자증권 비대면 우대 요율. **계좌마다 다르므로** `KR_COMMISSION_RATE` 로 교체 |
| 증권거래세 (매도) | `0.20%` | **2026년부터 0.15% → 0.20% 환원.** 코스피는 거래세 0.05%+농특세 0.15%, 코스닥은 거래세 0.20% |
| 국내 상장 ETF | `0%` | **증권거래세 면제.** 같은 폭을 먹어도 훨씬 유리합니다 |

```js
C.settlement({ buyPrice: 10000, qty: 1000, sellPrice: 10025 })
// → { totalBuyCost: 10000363, sellTax: 20050, netProfit: 4223, netReturnRate: 0.0422, ... }
```

**본전가 — "얼마에 팔아야 손해가 아닌가"**

비율만 계산하면 10,000원짜리의 본전은 +0.208%(=10,020.8원)입니다. 그런데 **1만원대 코스피 호가단위는 10원**이라
10,020.8원이라는 가격은 존재하지 않습니다. 실제로는:

| 매도가 | 순손익 |
| --- | --- |
| 10,020원 | **−767원** (올랐는데 손실) |
| 10,030원 | +9,212원 |

그래서 `breakevenPrice()` 는 호가 단위까지 반영한 **진짜 본전가(10,030원, +0.30%)** 를 냅니다.
같은 조건에서 ETF 는 거래세가 없어 본전가가 **10,010원(1호가)** 로 내려갑니다.

화면에서는 주문창·플랜·보유 목록에 본전가가 뜨고, 보유 손익은 **비용을 뺀 세후 금액**이 앞에 표시됩니다.

### 손익·손절을 숫자로 직접 입력

봉이 닫히기를 기다리지 않고 **체결틱 하나하나로** 손절·목표를 확인합니다.
그래서 10초봉을 보든 10분봉을 보든 청산 시점은 똑같고, 기준만 원하는 단위로 넣으면 됩니다.

| 청산 기준 | 입력 | 예 |
| --- | --- | --- |
| `signal` | — | 신호 엔진이 변동성(ATR)에 맞춰 자동 |
| `percent` | 손절 %, 목표 % | 손절 -1.0% / 목표 +1.5% |
| `amount` | 손절 원, 목표 원 | 손절 -30,000원 / 목표 +50,000원 (수량으로 나눠 주당 환산) |
| `ticks` | 손절 호가, 목표 호가 | 손절 -3호가 / 목표 +8호가 |

어느 기준이든 **호가 단위에 맞춰 정렬**되고, 손절·목표는 진입가에서 최소 1호가 이상 벌어집니다.
트레일링 스탑은 % 또는 호가 수로 걸 수 있습니다.

수동으로 산 주식도 `자동 청산 걸기` 를 체크하면 같은 기준으로 감시합니다(시간 제한 없음).
주문 전에 손절·목표가 얼마가 되는지 화면에서 미리 볼 수 있습니다.

### 수량 결정 — 자동 계산 / 직접 입력

| 방식 | 동작 |
| --- | --- |
| `자동 계산` | 계좌 잔고 · 1회 위험(%) · 1회 투입액(원)에서 수량을 역산 |
| `직접 입력` | 신호가 뜨면 **항상 입력한 주식 수**로 매수. 1회 투입액 한도를 적용하지 않음 |

직접 입력이어도 **주문가능현금은 넘지 못합니다** — 모자라면 살 수 있는 만큼만 사고 그 사실을 로그에 남깁니다.

### 주문이 실제로 나가기까지 — 안전 관문 7개

1. 엔진 `enabled = true`
2. 킬스위치가 눌리지 않았을 것
3. 정규장 시간일 것 (동시호가·시간외 진입 금지)
4. `dryRun = false` — **기본값이 `true`(모의 실행)** 라 켜기 전엔 주문이 나가지 않습니다
5. 실전 계좌라면 `allowLive = true` 까지 명시적으로 켜져 있을 것
6. 일일 손실한도 · 일일 주문수 · 동시 보유종목 · 1회 투입액 한도 이내일 것
7. 같은 종목에 진행 중인 주문이 없을 것

하나라도 막히면 주문 대신 **사유가 로그에 남습니다**. 재기동하면 `enabled` 와 `allowLive` 는 항상 꺼진 채로,
킬스위치는 눌린 채로 복원됩니다.

> **단 하나의 예외** — 실제로 체결된 포지션의 **청산**은 `dryRun` 이나 `allowLive=false` 여도 주문이 나갑니다.
> 진짜 산 주식이 설정 때문에 못 팔리는 상황을 만들지 않기 위해서입니다. 모의 진입은 모의로만 청산됩니다.

> ⚠️ 실전 자동매매입니다. 반드시 **모의투자 계좌에서 충분히 돌려 본 뒤** 실계좌로 옮기세요.

## 실행

```bash
node server/server.js          # http://127.0.0.1:5173
```

실행 옵션은 **환경변수 대신 명령줄 플래그**로 받습니다. 환경변수 문법은 운영체제마다 달라
(윈도우 CMD `set X=1` / 파워셸 `$env:X="1"` / 맥·리눅스 `X=1 명령`) 가장 많이 막히는 지점이기 때문입니다.

```bash
node server/server.js --mobile        # 같은 와이파이의 휴대폰에서도 접속
node server/server.js --port 8080     # 포트 변경
node server/server.js --demo          # 데모 데이터로 실행
```

기존 환경변수 방식(`HOST` · `PORT` · `MOCK`)도 그대로 동작하며, 플래그가 우선합니다.

| 명령 | 설명 |
| --- | --- |
| `npm start` | 실시간 시세(Yahoo Finance) 사용, 실패 시 데모 데이터로 자동 전환 |
| `npm run demo` | 항상 데모 데이터 (오프라인·사내망 등 외부 접속이 막힌 환경) |
| `npm test` | 지표·신호·초단타·AI 엔진 단위 테스트 |
| `PORT=8080 node server/server.js` | 포트 변경 |
| `npm run mobile` | 같은 와이파이의 휴대폰에서도 접속 (`--mobile`, 운영체제 무관) |

### 앱처럼 설치하기

세 화면 모두 웹 매니페스트를 제공하므로 브라우저에서 **앱으로 설치**하면
주소창 없는 독립 창으로 열리고 바탕화면·홈 화면에 아이콘이 생깁니다.

휴대폰에서 보려면 `npm run mobile` 로 실행한 뒤, 터미널에 출력되는 LAN 주소

`KIS_UI_TOKEN` 을 설정해야 외부 기기에서도 허용됩니다 (`?token=...` 또는 `x-ui-token` 헤더).

Node.js 18 이상이면 되고, 차트·초단타 기능은 **의존성 없이** 그대로 돕니다.

시세는 API 키가 필요 없는 Yahoo Finance 공개 차트 엔드포인트를 서버가 대신 호출합니다(브라우저 CORS 우회 + 짧은 캐시).
외부 접속이 막혀 있으면 상단 배지가 `데모 데이터`로 바뀌고, 화면 구성과 모든 기능은 동일하게 동작합니다.

- 가격/RSI 도달 알림 (브라우저 알림 + 화면 토스트)

| 구분 | 판정 내용 | 가중치 |
| --- | --- | --- |
| 이동평균 | 정배열/역배열, 단기-중기 골든·데드크로스 | 8 ~ 18 |
| VWAP | 당일 평단 위/아래 (단타의 기준선) | 12 |
| 볼린저밴드 | %B 위치, 밴드 이탈 후 회복, 스퀴즈(밴드폭 백분위) | 6 ~ 12 |
| RSI | 과매수/과매도, 50선 돌파 | 6 ~ 10 |
| MACD | 히스토그램 0선 전환(골든·데드크로스), 부호 | 7 ~ 14 |
| 스토캐스틱 | 과매도/과매수권에서의 %K-%D 교차 | 10 |
| 거래량 | 20봉 평균 대비 배율(급증/부족)과 캔들 방향 | 7 ~ 14 |
| 추세선 | 자동 추세선(스윙 고·저점 연결) 돌파·이탈 | 16 |
| 지지/저항 | 스윙 가격대 군집화 후 근접 여부 | 8 |
| 캔들 패턴 | 장대양·음봉, 망치형, 유성형, 장악형, 도지 | 9 |

**매매 플랜**은 손절을 `1.2 × ATR(14)`로 잡고, 1차 목표는 `1.5R`(가까운 지지/저항이 있으면 그 레벨), 2차 목표는 `2.5R`로 제시합니다.
손익비가 1.5 미만이면 빨갛게 표시되니, 진입 전 손익비부터 확인하세요.

## 알아두면 좋은 점

- **지연 시세입니다.** Yahoo Finance 공개 데이터는 실시간 체결가가 아니라 보통 15분가량 지연됩니다. 실제 초단타 체결에는 증권사 실시간 시세를 쓰세요.
- 자동 새로고침은 봉 주기에 맞춰 20초~5분 간격이며, 백그라운드 탭에서는 멈춥니다.
- 야후 API 제약으로 1분봉은 최근 5일까지만 조회됩니다(주기별로 선택 가능한 기간이 자동 제한됩니다).
- VWAP은 당일 세션 기준이라 일봉에서는 자동으로 비활성화됩니다.
- 관심종목·지표 설정·직접 그린 추세선·알림은 브라우저 localStorage에 저장됩니다.
