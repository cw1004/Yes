# 클릭 게이트웨이 & 번들 편성

영상 한 편에 제품 6개를 싣고, 각 슬롯의 클릭을 따로 추적하는 서버입니다.

```bash
cp ../.env.example ../.env      # 값 채우기
npm run serve                    # 게이트웨이 (기본 :8787)
npm run bundle                   # 후보 → 세트 1개 편성 (CLI)
npm run bundle my-candidates.json
```

## 왜 게이트웨이를 거치나

영상은 한 번 올라가면 캡션의 링크를 못 바꿉니다. 제휴 링크는 품절·가격 변동·정책으로
수시로 죽습니다. 자체 도메인을 앞에 세우면 뒤에서 목적지만 갈아끼우면 됩니다.

부수 효과로 두 가지를 얻습니다.

- **키 보호** — 쿠팡 시크릿키가 브라우저에 나가지 않습니다.
- **슬롯 단위 귀속** — `/go/{번들}/{슬롯}?src=reels` 로 어느 영상의 몇 번째 링크가,
  어느 채널에서 눌렸는지가 잡힙니다. 조회수보다 이 숫자가 중요합니다.

## 왜 6개인가

쿠팡·아마존 모두 어트리뷰션이 *클릭한 그 상품*이 아니라 *클릭 후 시간창 안의 구매*에
걸립니다. 링크가 6개면 진입점이 6개가 되고, 한 번 들어간 사람이 창 안에 산 다른 것도
실적에 잡힙니다.

> **확인 필요**: 이 규칙과 시간창 길이는 각 프로그램 약관 항목입니다. 배치로 돌리기 전에
> 본인 계정 약관에서 확인하세요. `config.mjs`의 `ASSUMPTIONS.attributionHours`가 그 값입니다.

## AI가 하는 일과 하지 않는 일

| | 담당 | 이유 |
| --- | --- | --- |
| 수수료율·전환율·EPC·클릭 배분 | `scoring.mjs` (산술) | 돈을 움직이는 숫자입니다. 재현 가능하고 감사 가능해야 합니다 |
| 세트가 한 방으로 읽히는지, 후크 카피, 슬롯 순서 | `bundle.mjs` (Claude) | 모델이 실제로 잘하는 판단입니다 |

**모델은 수수료율이나 예상수익을 반환하지 않습니다.** 환각된 숫자가 지출 결정을 조용히
움직이는 걸 막기 위해서입니다. `ANTHROPIC_API_KEY`가 없으면 세트 구성만 휴리스틱으로
내려가고 수익 계산은 동일하게 동작합니다.

## 수익 모델

```
제품 EPC = 판매가 × 수수료율 × 전환율
전환율   = 기본전환율 × 할인계수 × 리뷰계수 × 평점계수 × 가격대계수
번들 EPC = Σ(슬롯 EPC × 슬롯 클릭배분)
최종점수 = 번들 EPC × 콘텐츠 적합도
```

계수는 전부 `config.mjs`의 `ASSUMPTIONS`에 모여 있습니다. **전부 추정치입니다** —
실제 클릭 로그가 쌓이면 `slotClickShare`와 `baseConversion`부터 실측으로 교체하세요.

## 엔드포인트

| | |
| --- | --- |
| `GET /go/:번들/:슬롯` | 클릭 기록 후 302. 기록이 먼저라 리다이렉트가 실패해도 데이터는 남습니다 |
| `GET /b/:번들` | link-in-bio 랜딩 페이지. 인스타·틱톡은 캡션 링크가 안 눌리므로 필수 |
| `POST /api/bundles` | 후보 목록 → 세트 편성 |
| `GET /api/clicks` | 슬롯별 클릭 집계 |

## 저장소

의존성을 줄이려고 파일에 씁니다 (`.data/`, git 제외).
`bundles.json`, `clicks.jsonl` 둘 다 `cat`으로 읽힙니다. 규모가 커지면 교체하세요.
